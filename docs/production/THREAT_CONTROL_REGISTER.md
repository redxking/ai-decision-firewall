# Stage A Threat-Control Register

**System state:** production-development candidate
**Candidate:** unreleased `0.4.0-alpha.2`; implementation Commit `8818d5d2d40faebced66a254d58b1f0d04c9f8b4` published on `main`
**Baseline:** `bb6b8f28afba0961bb97b24e6050fccaa94d5702`; exact evidence in [`ADF-STAGE-A-ER-002`](STAGE_A_RECEIPT_RESULT_EVIDENCE_RECORD.md)
**Scope:** single-host, offline, synthetic-only Stage A
**Authority:** no historical or live data, production connector, operational credential, production target, or model-promotion authority

## Decision use

This register maps every threat required by the production-completion prompt to the control currently present, the negative test or evidence obligation, detection, response, residual risk, and current status. It is a release-blocking register, not an assertion that the controls are operationally effective.

The current opt-in Stage A increment may persist authority and terminal-result state in a schema-v2 control SQLite database and synthetic target state plus adapter receipts in a separate schema-v1 adapter SQLite database. The JSONL lifecycle audit is a third artifact. The three paths are pairwise distinct, and their transactions are not atomic across stores. Bounded POSIX directory locks serialize cooperating first-open and durable operations; an exclusive audit-file lock owns each JSONL lifecycle. Full per-store semantic/chronological scans and startup/runtime cross-store correlation detect defined divergence. These controls do not create OS isolation, external audit custody, independently custodied observation, a distributed fence, HA/DR, a vendor adapter, or a live-effect path. Any status below is bounded to repository-controlled, offline synthetic execution.

### Status vocabulary

| Status | Meaning |
|---|---|
| `BASELINE_TESTED` | Implemented and exercised at or before the stated baseline; still synthetic CE-1 evidence only. |
| `STAGE_A_CANDIDATE` | Implemented or documented in published exact Stage A Commit `8818d5d2`; project-controlled verification exists, but the named production property and owner acceptance remain incomplete. |
| `PARTIAL` | A bounded control exists, but a material production property is absent. |
| `OPEN` | No adequate implementation or objective acceptance evidence exists. |
| `EXTERNAL_AUTHORITY_REQUIRED` | Completion depends on an accountable owner, approved system, or authorization outside this repository. |

## Non-negotiable invariants

1. Model output, agent recommendation, and confidence never create authority.
2. Unknown identity, evidence, policy, target, consequence, authorization, audit, or verification state fails closed.
3. A possible effect is never reported as success. `APPLIED`, `PARTIAL`, or `AMBIGUOUS` adapter receipts without separately durable verification, and absent receipts, reconcile to `UNKNOWN_EFFECT`; they are never automatically retried.
4. Stage A permits only the closed `synthetic_simulation` path, either with the compatibility in-memory target or the opt-in offline `SQLiteSyntheticAdapterStore`; no external adapter or network target is permitted.
5. A `SyntheticAdapterReceipt` is adapter-reported only. Separate observation of the same adapter database is not independent target evidence.
6. `RequestLookupResult` is a closed, sanitized, authority-free replay envelope, not `Phase3Result`; lookup never creates a new decision, authorization, command, effect, or audit lifecycle.
7. Recovery audit uses the exact contiguous sequence `RECOVERY_STARTED`, `RECOVERY_EVIDENCE_ASSESSED`, and `RECOVERY_FINALIZED`; an uncommitted trio or prefix owns the audit tail and other audit writers fail closed until exact recovery reaches T3.
8. Green tests or a valid manifest do not establish source truth, production safety, operational effectiveness, or authorization.
