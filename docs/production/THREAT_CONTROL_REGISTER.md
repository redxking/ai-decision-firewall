# Stage A Threat-Control Register

**System state:** production-development candidate
**Baseline:** `bb6b8f28afba0961bb97b24e6050fccaa94d5702`
**Scope:** single-host, offline, synthetic-only Stage A
**Authority:** no historical or live data, production connector, operational credential, production target, or model-promotion authority

## Decision use

This register maps every threat required by the production-completion prompt to the control currently present, the negative test or evidence obligation, detection, response, residual risk, and current status. It is a release-blocking register, not an assertion that the controls are operationally effective.

The current Stage A increment may persist request, authorization, and attempt state in a local SQLite ledger. It does not create OS isolation, external audit custody, a distributed system, a vendor adapter, or a live-effect path. Any status below is bounded to repository-controlled synthetic execution.

### Status vocabulary

| Status | Meaning |
|---|---|
| `BASELINE_TESTED` | Implemented and exercised at or before the stated baseline; still synthetic CE-1 evidence only. |
| `STAGE_A_CANDIDATE` | Implemented or documented in the current local Stage A increment; exact commit, full regression, manifest, and CI remain required. |
| `PARTIAL` | A bounded control exists, but a material production property is absent. |
| `OPEN` | No adequate implementation or objective acceptance evidence exists. |
| `EXTERNAL_AUTHORITY_REQUIRED` | Completion depends on an accountable owner, approved system, or authorization outside this repository. |

## Non-negotiable invariants

1. Model output, agent recommendation, and confidence never create authority.
2. Unknown identity, evidence, policy, target, consequence, authorization, audit, or verification state fails closed.
3. A possible effect is never reported as success. An incomplete durable attempt becomes `UNKNOWN_EFFECT` and is never automatically retried.
4. Stage A permits only the closed `synthetic_simulation` path and in-memory synthetic target state.
5. Green tests or a valid manifest do not establish source truth, production safety, operational effectiveness, or authorization.

## Required-threat coverage check

The register explicitly covers: malicious/compromised agents (TC-01); credential theft and confused deputy (TC-02); evidence forgery, replay, poisoning, omission, and cross-target substitution (TC-03); policy manipulation and downgrade (TC-04); target-inventory tampering (TC-05); authorization replay, scope mutation, and expiry races (TC-06); approval forgery and automated human impersonation (TC-07); broker bypass and direct target access (TC-08); audit loss, truncation, replacement, and ambiguous write failure (TC-09); model extraction, evasion, and adversarial examples (TC-10); dependency/build compromise (TC-11); insider misuse (TC-12); denial of service and request-ledger poisoning (TC-13); multi-tenant data/authority leakage (TC-14); and partial failures/split brain (TC-15).

## Release decision

Stage A may be described only as a **single-host synthetic/offline production-development candidate** after its exact commit, manifest, focused and full suites, and CI are frozen and reverified. This register does not support a production-ready, pilot-ready, historically validated, independently assessed, or operationally effective claim.
