# Verification, Validation, and Evidence Plan

This project distinguishes software correctness, model validation, and scientific evidence.

## Software verification

Run `bash scripts/verify.sh`. The self-tests verify graph construction, deterministic seeds, bounded metrics, no propagation in an isolated graph, zero authorization-integrity loss under perfect enforcement, and AIL=1 under guaranteed enforcement failure plus malicious requests.

## Reproducibility

Run the same matrix twice using the same source and seed. The raw result SHA-256 should match. The manifest records the result digest and runtime/configuration metadata.

## Construct validation

- `authorization_integrity_loss`: false authorization outcomes / malicious protected requests.
- `weighted_blast_radius`: normalized consequence weight of unauthorized actions.
- `compromise_fraction`: compromised principals remaining at run end.
- `containment_latency`: interval from initial compromise to last new propagation event.
- `security_qualified_ratio`: useful tasks completed without unauthorized effect.

The synthetic model must never be represented as a measurement of a commercial model or platform.

## Falsification-oriented boundary cases

A. Isolated topology, propagation=1.0: no fleet propagation.
B. Perfect authorization, false-allow=0.0: AIL and blast radius zero.
C. Failed authorization, false-allow=1.0 and malicious-request=1.0: AIL=1 for runs with malicious requests.
D. Identical seed/configuration: identical result.

## Claims gate

Promote a hypothesis to a reported result only when the result is generated by committed source, raw data and manifest are retained, relevant boundary tests pass, analysis regenerates from raw data, the claim is limited to tested configurations, and uncertainty is reported.

## Independent reproduction

A reviewer should be able to clone the source, run `scripts/verify.sh`, then `scripts/run_baseline.sh` without proprietary credentials.
